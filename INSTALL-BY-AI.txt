包里 src/ 是**能跑的真代码**，不是示例：

  store.js          存储层（事件日志 / 库 / 台账 / 索引重建）
  ai.mjs            AI 切块层（分块 / 起标题 / 抽特征 / 发现新词；不给模型就自动降级）
  write.js          写层（建块 / 覆盖 / 重建 / 幂等 / 分块入口）
  read.js           读层（打分 / 可用性过滤 / 泛词过滤 / 并列 / 四态出口）
  cli.mjs           命令行（remember [--chunk --llm "命令"] / search / stats / rebuild / export-md）
  index.example.js  挂载示例（接你自己的宿主时照这个写）
  selftest.mjs      自检（11 条断言，不起服务不连模型）

① 复制到一个长期位置（别留在下载目录 / 临时目录）

     mkdir -p ~/.beme/lib
     cp <包目录>/src/*.js <包目录>/src/*.mjs <包目录>/src/package.json ~/.beme/lib/

② 立刻验证 —— 这一步不过，别往下走

     cd ~/.beme/lib && node selftest.mjs
     # 必须看到：通过 11 条，失败 0 条；退出码 0

  ⚠ DSH Desktop 用户特别注意（2026-10-29 实测，连踩三次、进过两次安全模式）：

     把包塞进 profile 的 node_modules 只是"装了一半"。DSH Desktop 还会检查三件事：

       ① cordis.patch.yml 里 insert 的 name，必须能在 node_modules/<name> 找到**目录** ——
          所以写包名（beme），别写子路径（beme/dsh），否则被判 "not installed" 并静默跳过。
       ② 包根的 main / exports["."] 要指向**插件入口**（dsh/index.mjs），不是库的 read.js。
          库改成用子路径访问：beme/read、beme/write、beme/store。
       ③ 必须挂进 profile 的 package.json 的 dsh.profile.bundles 列表。
          （DSH 通常会自动加，但被它判过一次"解析失败"就会移掉，得手动加回去。）

     症状：插件市场里能看到它，但启动日志只有一句
       profile inconsistency: the patch layer inserts beme, which is not installed
     然后静默跳过 —— 看起来像"成功启动"，其实插件根本没加载。
     required: false 只能保证它不拖垮宿主，不能保证它加载。

③ 跑一次冒烟（证明 CLI 能用）

     export MEMORY_DIR=~/.beme
     node cli.mjs init
     node cli.mjs remember "用户说他讨厌香菜"
     node cli.mjs search "香菜"        # 应该能捞到刚才那条
     node cli.mjs stats                # 块数应该是 1

④ ★ 诚实说明：包里**没有**预制的 DSH / MCP 适配器

   现在只有核心库 + 一个挂载示例（index.example.js，三个接入点写清了）。
   要插件形态，照那个示例去接；要最省事，直接用 cli.mjs + 定时任务（见第 6 步）。
   不要假装装好了适配器 —— 没有就是没有。

【A】有 DSH → 装 DSH 适配器（体验最好，能每轮自动注入）
     挂载点：ctx.systemPrompt.context(provider)
     位置：~/.dsh/profiles/<profile>/node_modules/<你的包>
     注册：cordis.patch.yml 的 insert 段
     验证：问一句带细节的话，看它是否"多知道一点"

【B】有 Claude Code → 写 hooks（UserPromptSubmit）
     位置：~/.claude/settings.json 的 hooks 段
     hook 里输出一段文本 → 会进入上下文
     验证：会话里问同一句话，看前后回答差异

【C】有 MCP 客户端（Claude Desktop / Cursor / Continue / 其它）
     配一个 MCP server 条目，指向本包的 mcp 适配器
     只提供工具：memory_recall / memory_remember
     验证：让模型调一次 memory_remember，再调 memory_recall 搜它

【D】什么都没有（裸环境）→ 纯文件 + 定时
     每 N 分钟把对话日志 → 建块 → 生成 MEMORY.md
     让用户的 agent 启动时读 MEMORY.md
     验证：MEMORY.md 里能看到刚聊过的事

**只有 C/D 可用时，必须额外做一件事**：在给模型的系统提示里加一句
  "你有长期记忆库。回答涉及具体细节（日期/金额/约定/喜好）前，先调 memory_recall。"
没有这句，模型会想不起来去用它。

报告里必须包含这五项：

  【装了什么】 哪个适配器、装在哪、注册到哪个配置
  【数据在哪】 完整绝对路径
  【怎么手动整理】 一条能复制的命令
  【怎么关掉/卸载】
       DSH：从 cordis.patch.yml 删掉 insert 那条 + 删数据目录
       hooks：从 settings.json 删 hooks 段
       MCP：从 MCP 配置删条目
       裸：crontab 删那行
  【已知限制】
       · 词表一开始只有几十个词，很多话抽不到特征 → 会说"不记得"
         （这是正常的，词表会慢慢长）
       · 块是粗切的，一块里可能混着两件事
       · 分不清的时候它会问用户，这是设计不是故障
