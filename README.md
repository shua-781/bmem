## 那天早上

有天早上，我问它："昨天说的那件事，定了吗？"

它答得很顺，语气也对，但内容全是它自己编的。

那种感觉很奇怪——它不是在骗我，它是真的不知道。它只是**接得很自然**。
它越想显得没忘，就越像忘干净了。

后来我去翻聊天记录，翻到了昨天的那几句。**东西一直在那里，只是不在它眼前了。**

那天我才想明白一件很别扭的事：

> **AI 的记忆问题，从来不是"它忘了"，是"它不知道自己忘了"。**

---

## 我以为是不够长

我一开始的判断很朴素：**那就让它记得更多**。

加长上下文、多塞记忆、把重要的事反复提。我做了一版又一版，效果都很微妙——**它好像记得，又好像不记得**。

直到我把参数翻出来看：

```
上下文窗口      1,000,000 token
压缩触发阈值    80%（八十万 token 才会压成十六万）
一天聊天        687 轮 / 20 万字 ≈ 32 万 token
```

**三十二万，连窗口的三分之一都不到。**

剩下那六十多万是空的。可它还是会忘。

那一刻我明白自己一直在修错的东西。

> **紧的从来不是窗口，是注意力。**
>
> 塞 200 条记忆进去，它只会认真看前 20 条。
> 剩下的在上下文里，但等于不在。

所以"多记一点"这条路，从一开始就走不通。**问题不是装不下，是装进去也白装。**

---

## 人是怎么记得的

那怎么办？

我想了想人是怎么过日子的。

人也会忘。但人的忘有个特点：**忘了的东西，通常能找到回来的路**。
你忘了朋友姓什么，但你知道去翻通讯录；你忘了去年哪天去的医院，但你知道去翻病历。

**人不是记住了一切，人是留了索引。**

于是这个问题就变形了：

> 不是"怎么让它记得更多"，
> 而是"**怎么让它忘得有结构，需要时还找得回来**"。

---

## 一个念头

真正的转折是这句（当时是被一个很朴素的提问逼出来的）：

> **"既然它都要忘，那忘掉的东西，能不能先做成卡片存起来？"**

能。而且一旦这么想，很多事就顺了。

我把它现在的处境画成一张桌子：

```
┌──────────────────────────────────────────┐
│  桌子（上下文）                          │
│  今天正在聊的东西，全摊在上面             │
│  桌子有限，堆满就得收走                   │
│  收走的 = 从它眼前消失                    │
└──────────────────┬───────────────────────┘
                   │ 要收走之前，先把那张纸做成卡片
┌──────────────────▼───────────────────────┐
│  档案室（块库）                          │
│  一张卡片 = 一件事的一个侧面              │
│  永久保存：不合并、不降级、不删            │
└──────────────────┬───────────────────────┘
                   │ 每张卡片都要登记
┌──────────────────▼───────────────────────┐
│  账本（只追加的事件日志）                 │
│  永不修改、永不删除。档案室坏了靠它重建    │
└──────────────────┬───────────────────────┘
                   │ 从账本派生（可随时重建）
┌──────────────────▼───────────────────────┐
│  目录（索引）                            │
│  特征→卡片、时间→卡片、类别→卡片…          │
└──────────────────────────────────────────┘
```

**关键在最后那张桌子之外的东西**：卡片不在它眼前。

所以白天的规则变得非常干净：

```
今天说的话  → 本来就在桌子上，不需要任何"缓存层"
昨天及以前  → 已经离开桌子，才需要去档案室找
```

这一条立刻帮我砍掉了一整块设计——原本我准备的"三级缓存：最近层 / 流式层 / 大池子"，**整套删掉，一点损失都没有**。因为"今天"从来不需要被缓存，它本来就在。

## 六条我不敢再破的规矩

接下来是六个决定，每一个都是拿一次崩溃换来的。

我管它们叫"铁律"，其实只是**六个我不敢再违反的地方**。

### 一、账本永远是真相，档案室只是它的一份当前视图

我犯过一次错：改了档案室，忘了记账本。三天后档案室被一次错误的合并弄坏，我想重建，才发现**账本里没有那段**——也就是那三天的记忆，从世界上消失了。

从那天起顺序焊死了：**先写账本，再写档案室。颠倒一次都不许有。**

同一个道理还救了我另一个问题。我原本很怕"让 AI 来判断这件事该不该合并"，因为**AI 的判断不可复现**——同样的话问两遍，答案可能不一样。

后来我想通了：

> **那就只让它判一次。判完就把结论记进账本。以后只读账本，绝不再问第二遍。**

"不可复现"这个问题，不是靠更强的模型解决的，是靠**"判一次，判完即存档"**解决的。

### 二、卡片永不扔

我原本设计了一整套"生命周期"：不重要的降级、相似的合并、没用的归档、删掉的留个墓碑。

后来全废了，理由只有一句话：

> **删是不可逆的，不翻是可逆的。**
> 在"可逆"和"不可逆"之间，永远选可逆。

而且"当时不重要"从来不等于"以后不重要"。用户随口提过一句"我讨厌香菜"，当时谁也没在意；半年后做饭的时候，那就是最重要的那一条。

**所以卡片只增不减。空间是全世界最便宜的东西，误删不是。**

### 三、一张卡只装一件事

这条最反直觉，因为它意味着**同一件事会被拆成好几张卡**。

但反过来更可怕：如果把两件不同的事压进一张卡（在我原来的设计里叫"覆盖"），**所有索引都会指向那个错误的答案，而且不会报错**。

静默的错，比明显的错贵一百倍。

所以判不准的时候一律新开一张。多一张卡只是多占几 KB，压错一次就是永久性的污染。

### 四、档案室里只放"已经离开桌子"的东西

这条是整套东西能转起来的枢纽。

我最初打算"每轮对话都记一笔"。算了一下：一天 687 轮 → 345 张卡/天 → **一年十二万张**。

不是装不下，是**碎到没法用**。十二万张卡片里，任何一张单独拎出来，都只有半句话。

所以真正的时机不是"每聊一句就记"，而是：

```
桌子要收东西的那一刻  ← 这才是唯一精确的时机
```

具体来说就是：上下文要压缩的时候、对话要归档的时候、换日的时候、桌子快堆满的时候。

**卡片是那张纸"曾经在桌子上"的唯一证据。** 不是日记，是墓碑。

### 五、卡片是碎片，答案是拼出来的

一张卡片一百多 token。它装不下"那杯奶茶到了没、多少钱、几点点的"。

这三件事是散在三张卡里的。

所以正确用法不是"抽一张出来念"，而是：

```
多抽几张 → 按同一件事聚成一条线 → 拆成"要答的几个空" → 逐个填 → 拼成一句话
```

**而拼不齐的时候，必须说拼不齐。**

### 六、用户是裁判

```
分数离得近，分不清是哪一件 → 问用户："你说的是哪一件？"
一个能用的特征都抽不到   → 问用户
档案室里确实没有         → 说"我不记得"
```

我一开始很抗拒这条——觉得"什么都要问，那要记忆干什么"。

后来想明白了：**机器负责"找得全、算得快"，人负责"这说的是哪一件事"。**

这两件事本来就该分工。而且，**机器猜错一次，比问一句贵十倍**。

## 我用掉的十四种错误

然后是十四次失败。

这部分我觉得比方案本身值钱——因为方案是"我选了这条"，而失败是"这条路为什么走不通"。

**关键词检索**。听起来最自然，实际上有六种硬伤。最要命的一种是代词："上次说的那个"——**它连一个关键词都没有**。

**固定长度坐标**。我一开始想给每张卡算一个 256 位的坐标，靠距离找相似。看起来很美，直到我想明白：特征种类会超过位数，那时候扩容等于全库重算。

**字面相似扩散**。我想从"象棋的几个走法"自动长出"象棋"这个概念。跑出来 3/12——因为 `兵七进一` 和 `炮二平五` **一个字都不重合**。字面看不见结构。

**共现聚类**。同一个东西总一起出现，那总能聚出来吧？也不行："象棋"这两个字那天一次都没在对话里出现过——**上位词压根不在语料里**。统计能长出树叶，长不出树枝。

**三级缓存**。就是前面说的那套。上下文本身就是缓存，整套删掉零损失。

**用分数除以根号 token 来选卡**。这是我最后悔的一个设计，因为它**看起来非常合理**：同样的分数，短卡片信息密度更高，应该优先。实测下来：平均卡片从 191 token 压到 **43 token**，token 预算只花掉 41%，选出来的 6 张**全都跟问题无关**。

**卡片生命周期**。降级、合并、归档、墓碑。删不可逆，全废。

**链式传播**。一件事变了，通知相关的一批；那批再通知它们相关的……四五跳之后覆盖全库，**而且永远收敛不了**（权重变了又算一次"变化"）。换成广播：只说一句"来了个新东西"，绝不去改别人的关系。

**全靠规则判断"是不是同一件事"**。真实口语里，规则**只能判出 16.9%**。为什么？因为 66.6% 的句子根本没有主语——中文口语就是这样的。

**隐私一律整块打码**。听起来最安全，实际上把答案打残了：问"订单号多少"，那块因为含地址被整块丢掉，于是它答不出来。

**每轮实时建卡**。一天三百多张，碎到没法用，而且写的时候判错就是静默指错。

**用绝对阈值判断"有没有把握"**。设了个 0.55，结果 top8 的分数是 0.843 / 0.843 / 0.842……**差 0.001 却全部越过了阈值**。分数是相对量，只看绝对值等于没看。

**按序号打破并列**。这意味着最早建的那张卡永远赢——一个完美的时间偏置。

**没有全局序号**。我最后一版设计毁在这上面：每个会话各自从 0 开始编号。等到要重放账本的时候，33 个会话的编号全撞在一起，**根本分不出先后**。

还有一个是系统级的：

> **结构复杂度和脆弱度成正比。**

每加一层机制，就多一个可能坏、需要维护的地方。所以我后来给自己定了三条反向纪律：

```
能砍就砍 —— 一个机制三个月没发挥作用，砍掉
能浅不深 —— 分类到"科"够用，就别下到"属"
能不做就不做 —— 加一层之前先问："不加会怎样"
```

## 最后跑出来的样子

最后跑出来的东西长这样（数字都是那一天的真实对话）：

```
那一天     687 轮 / 20 万字
去掉重复   49.8% 是重复的（这个数字吓到我了，去重没做好版本号会被垃圾刷爆）
一张卡片   中位 125 token
规则判得准 16.9%（所以必须两层：规则只判"否"，拿不准交给 AI）
一次检索   候选中位 89 张（所以注入和通知都必须封顶）
```

而我修掉的那几个病，症状都很具体：

```
问"这件事的细节"  → 注入的是"奶茶""表情包"（因为选卡用了根号 token）
问"光发表情什么意思" → 注入 1030 字全是发表情相关的记忆
                     → 它跟着只发表情，自我强化了好几轮
一段话里混着三件事  → 必须按句子切开，不然一张卡里塞三个话题
```

**最有用的一条发现是**：

> **"要答的槽填齐了" 不等于 "答对了"。**

有次问"这套东西定了没"，它把"是否"这个空填上了，然后自信地拼出一段完全不相干的内容。
从那以后，判断顺序就焊死了：**先看分数分不分得开，再看并列的是不是同一件事，最后才看槽填没填齐——三层串联，不许并联。**

## 它到底是什么

所以这东西到底是什么？

它不是让 AI 变聪明，**它是让 AI 的"忘"变得可回收**。

- 忘，仍然是设计的一部分
- 但忘掉的东西躺在档案室里，需要时能被翻出来
- 翻不齐的时候，它会诚实地问，而不是编

**它适合这样的场景**：一个 AI 要陪同一个人很久，久到"昨天"真的会丢。
**它不适合**：单次问答、无状态调用、或者要求 100% 精确的场合（比如记账）。

如果只能记住一句话，我希望是这句：

> **记忆的价值不在于"留得多"，在于"留得对"。
> 而不重要的东西不再是"被删掉"，是"暂时没被翻到"。**
